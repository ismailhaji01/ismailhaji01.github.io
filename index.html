About

I'm a software engineer and technical lead based in Dar es Salaam. Most of my work sits where money, devices and regulators meet: mobile money pushes and payouts, bank control numbers and card payments, biometric point-of-sale terminals, and vehicle telematics data that has to reach the regulator on time.

I own these systems end to end. I design the architecture, write the code in Laravel, Go and Kotlin, run production on Linux with Docker and Traefik, and work through integrations with each network's and bank's technical team until they go live.

Before EvMak I built secure web applications at the e-Government Authority and examined devices in cybercrime cases at Tanzania Police Headquarters. That background is why I care about authentication, audit logs and failure handling as much as features.

01 · PaymentsLive

EvPay Payment Gateway

One API that lets merchants collect and pay out across Tanzania's mobile money networks and banks, so they integrate once instead of separately with each provider.

  • Modular design with a separate module for each provider: Vodacom M-Pesa, Mixx by Yas (Tigo), Airtel Money, HaloPesa, CRDB, NBC and NMB.
  • Supports USSD push, C2B, biller and payout (B2C) flows, plus bank control numbers and card payments.
  • A provider router sends each request to the right network. Each network has its own log, and queued status checks catch payments whose callback never arrives.

02 · PerformanceLive

EvPay Go transaction service

A Go service for EvPay's transaction API, built for high throughput and to keep running without manual intervention.

  • A worker pool and job queue process transactions concurrently, with drop and throughput statistics for monitoring.
  • Provider clients for M-Pesa, Mixx by Yas, Airtel Money and HaloPesa, with token caching and automatic retries.
  • Reconciliation endpoint with SMS alerts, a systemd watchdog that checks database health, and graceful shutdown.
